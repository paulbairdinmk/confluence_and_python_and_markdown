When an internal Markdown link jumps to the top of the page instead of scrolling to the target heading, it almost always means the anchor slug (ID) in your link doesn't match the ID generated by your Markdown parser.

Because standard Markdown doesn't natively define IDs, every platform (GitHub, Obsidian, VS Code, Notion, Jekyll, etc.) applies its own auto-generation rules to convert heading text into anchor IDs.

## 1. Common Anchor Slug Rules

Most platforms (including GitHub, GitLab, and standard CommonMark parsers) generate heading IDs using these transformation rules:
 * Convert all letters to lowercase.
 * Replace spaces with single hyphens (-).
 * Remove special characters and punctuation (like ?, !, :, ,, ., (, )).

Quick Examples:

| Your Heading | The Auto-Generated Anchor Link |
|---|---|
| ## Installation & Setup | [Go to Setup](#installation--setup) |
| ### Step 1: Download the App | [Go to Step 1](#step-1-download-the-app) |
| ## Frequently Asked Questions (FAQ)? | [Go to FAQ](#frequently-asked-questions-faq) |

## 2. Common Reasons It Fails
 * Incorrect Case: [Jump](#My-Heading) fails if the generator auto-lowercased it to #my-heading.
 * Unstripped Punctuation: [Jump](#what's-new?) fails because punctuation should be removed (#whats-new).
 * Missing # Prefix: [Jump](my-heading) treats the target as a relative web page rather than an internal page anchor.
 * Duplicate Headings: If you have two ## Setup headings in the same file, most parsers name the second one #setup-1.

## 3. Bulletproof Fixes
If platform auto-anchors are giving you trouble, use one of these two reliable fixes:

Fix A: Use Raw HTML Anchors (Works Almost Everywhere)
You can manually embed an HTML <a> or <span> tag inside or next to your heading. This bypasses the parser's auto-generated rules entirely:
<!-- The target heading -->
<a id="custom-setup-anchor"></a>Installation and Setup
 
<!-- The link to jump there -->
[Jump to Setup](#custom-setup-anchor)
 
Fix B: Use Explicit Attribute Syntax (Obsidian, Kramdown, Hugo, MkDocs)
If you are using Obsidian, Jekyll, Hugo, or an extended Markdown editor, you can assign custom IDs directly using attribute blocks:
## Installation and Setup {#my-custom-id}
 
[Jump to Setup](#my-custom-id)
 
4. How to Find the Exact Anchor ID
If you're writing for a web platform (like GitHub or a web-rendered Markdown preview):
 * Open the rendered Markdown page in your browser.
 * Right-click the target heading and select Inspect (or Inspect Element).
 * Look at the id="..." attribute generated on the <h1>-<h6> tag (or a nearby <a name="..."> tag). Use that exact string following a #.

You can create a custom anchor using raw HTML and then point standard Markdown links to it. Standard Markdown headings auto-generate anchors based on their exact text, but using an explicit HTML anchor gives you complete control over the target ID—even if heading text changes later.

Step 1: Set the Manual Anchor
Insert an HTML element with an id attribute directly above (or inline with) the target section:
<a id="my-custom-anchor"></a>

## RELATED DOCUMENTS <a id="related-documents"></a>
 
or using an empty span or div:
<span id="my-custom-anchor"></span>
 
Step 2: Link to the Anchor
In the Same File
Use a standard Markdown link starting with # followed by your custom ID:
Jump to the [custom section](#my-custom-anchor).
Eg 

See [Related Documents](#related-documents) section
   
> Note: VS Code's built-in Markdown preview supports custom HTML id targets seamlessly, allowing full navigation without relying on auto-generated heading strings.
